# QQ 闪传下载器

这是一个用于公开 QQ 闪传分享链接（`https://qfile.qq.com/q/...`）的 Go 命令行程序。直接启动程序后，粘贴链接并按提示操作即可。   
支持保留文件夹目录、自动解压缩、下载长度核对和哈希展示。

## 交互式下载

编译后直接运行，或在项目目录执行：

```powershell
go run .
```

程序流程如下：

1. 粘贴 QQ 闪传短链接并按 Enter，程序解析全部文件和目录。链接格式错误、分享失效或网络解析失败时，会显示原因并提示重新输入；直接按 Enter 可退出。
2. 再按 Enter，程序根据文件大小自动调节并发，下载全部可下载文件。
3. 下载完成后再按 Enter，程序只检查**本次下载的文件**中的 `tar`、`gz`、`xz`、`zstd` 压缩包和分卷，例如 `a.tar` 与 `a.tar.002`，或 `a.tar.001`、`a.tar.002`。
4. 单文件压缩包会直接解压；分卷会按编号顺序流式合并后解压。原始压缩包和分卷会保留。
5. 程序会展示本次下载文件及本次解压文件的 MD5、SHA-1、SHA-256。
6. 哈希展示完成后，按 Enter 退出。

文件会保存到程序的当前运行目录，并保持分享页的目录层级。文件名来自 QQ 分享页的元数据，而不是 HTTP 的 `Content-Disposition` 响应头，因此不会出现 `wget` 那类响应头解析导致的乱码或错名。若同名文件已存在，会保存为 `文件名 (1).扩展名`，不会覆盖原文件。

并发下载根据分享页提供的单个文件大小调度：

| 文件大小 | 同类文件最多同时下载 |
| --- | ---: |
| 不超过 20 MB，例如 10 MB | 10 个 |
| 超过 20 MB，不超过 200 MB，例如 100 MB | 5 个 |
| 超过 200 MB，不超过 1 GB，例如 500 MB | 2 个 |
| 超过 1 GB，或大小未知、无效 | 1 个 |

大小阈值按 1 MB = 1024 × 1024 字节、1 GB = 1024 MB 计算。混合大小的文件共用 10 格调度额度：以上四档分别占 1、2、5、10 格，例如可同时下载 1 个 500 MB 文件、2 个 100 MB 文件和 1 个 10 MB 文件。任务按分享列表顺序启动，前一个待下载文件额度不足时会等待；已有任务完成后及时补位。更大或大小未知的文件单独下载。

下载内容流式写入临时文件。分享元数据包含有效的非负字节数时，程序会在提交最终文件前核对实际长度，不足或超出均视为失败并清理临时文件；零字节文件也会核对。大小缺失、无效或溢出时仍可下载，但会明确提示“大小未知，未进行长度核对”。完整下载仅接受 HTTP 200，未请求的 HTTP 206 等响应会被拒绝。并发下载的重名文件也会自动编号。单个文件失败不会中止其他下载，全部任务结束后再进入解压和哈希流程。

`-timeout` 默认 `45s`，限制每次 QQ API 请求和下载响应头等待时间。`-download-idle-timeout` 默认 `2m`，限制下载响应体连续没有字节进展的时间，包括错误响应体；两个参数均须大于零。持续有数据进展的下载不受固定总时长限制。解析或下载期间按 Ctrl+C 会取消在途请求；下载取消后停止调度后续文件，清理临时文件并以非零退出码退出。

例如将响应头等待设为 60 秒、下载无进展超时设为 3 分钟：

```powershell
go run . -timeout 60s -download-idle-timeout 3m
```

支持单文件和编号分卷（`.NNN`）格式：

- `*.tar`
- `*.tar.gz` / `*.tgz`
- `*.tar.xz` / `*.txz`
- `*.tar.zst` / `*.tar.zstd` / `*.tzst`
- `*.gz`、`*.xz`
- `*.zst`、`*.zstd`

解压时会拒绝路径穿越，跳过符号链接等特殊归档项，并拒绝通过已有符号链接或目录联接写入目标目录。TAR 及压缩 TAR 先整组暂存，完成归档读取和压缩流尾部校验后才提交文件；后续条目损坏时不会保留前面的解压结果。提交中途失败时会回滚本组新建文件和空目录；清理失败会明确报告剩余路径。已有文件保持重名编号规则，失败组不计入成功数量或解压文件哈希列表。

哈希计算采用流式读取，不会一次性把大文件载入内存。程序仅展示当前文件的 MD5、SHA-1、SHA-256，没有可信的预期摘要供自动比较，因此不会报告“哈希校验通过”。长度一致也不能识别同长度的错误内容；如需核验内容，请将展示值与可信来源提供的摘要比较。MD5 与 SHA-1 仅用于兼容已有摘要，内容核验优先使用 SHA-256。

终端日志会将文件名、路径和远端错误中的控制字符转为可见转义文本，避免它们插入额外日志行或执行终端控制序列。

## 编译

```powershell
go build -o qfile-link.exe .
```

首次构建会下载纯 Go 的 `xz` 和 `zstd` 解压依赖。

## 保留的直链提取模式

给程序传入链接时，仍会输出 JSON 直链信息，方便脚本使用：

```powershell
go run . https://qfile.qq.com/q/TIRQPZgPUQ

# 输出经过转义的“文件路径<TAB>直链”
go run . -text https://qfile.qq.com/q/TIRQPZgPUQ

# 保存 JSON 输出
go run . -output links.json https://qfile.qq.com/q/TIRQPZgPUQ
```

`-text` 每个文件固定占一个物理行、两列，以真实 Tab 分隔，以 LF 结束。第二列为直链；文件不可用时为 `ERROR: ` 加错误信息。所有字段统一转义：反斜杠为 `\\`，Tab 为 `\t`，CR 为 `\r`，LF 为 `\n`，其他不可打印字符使用 `\xNN`、`\uNNNN` 或 `\UNNNNNNNN`；非法 UTF-8 字节使用 `\xNN`。普通中文、双引号等可打印字符保持原样。脚本先按真实换行和 Tab 分割，再还原字段中的反斜杠转义；需要保留原始结构化字段时可使用默认 JSON 输出。

例如，文件名含真实换行时会输出字面量 `\n`；文件名原本包含反斜杠和字母 n 时会输出 `\\n`，两者可以区分。文本或 JSON 输出遇到写入、短写、输出文件关闭错误时，程序会报告错误并以非零退出码退出。

QQ 可能随时调整网页协议；若接口发生变更，需要相应更新程序中的接口常量和请求格式。
